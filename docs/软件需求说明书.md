## 2. 项目背景与目标

### 2.1 使用情境

智能宿舍中，空调、照明、窗帘、加湿器和净化器通常彼此独立控制。用户需要频繁手动切换设备，也容易出现多个自动化策略同时控制同一设备而产生冲突。本项目提供一个离线可运行的规则编排沙盘：用户先设计“满足条件时执行设备动作”的联动规则，再调节模拟传感器数据或选择场景，观察规则引擎如何匹配条件、按优先级执行和记录冲突。

### 2.2 项目目标

1. 提供 4 项可调 Mock 环境数据：温度、湿度、光照、CO₂。
2. 提供 5 类可控设备：主灯、空调、窗帘、加湿器、净化器。
3. 支持规则的新增、编辑、启停、删除，规则包含 1—2 个条件（且关系）和 1—3 个动作。
4. 规则引擎根据真实输入计算触发结果，记录触发条件、设备变化、执行顺序和冲突仲裁。
5. 提供至少 2 组场景演练；本项目内置 4 组。
6. 使用 Preferences 持久化环境、设备、规则和日志，应用进程被结束后可恢复。
7. 提供不少于 6 条自动化测试；本项目共 17 条，覆盖正常、边界和异常。

### 2.3 范围与非目标

- 本应用为离线模拟应用，不连接真实硬件、云平台或在线账号。
- 不实现 3D 展示、语音控制或 AI 剧情生成。
- 设备状态由规则动作和手动调节共同改变；规则只执行已定义的“开启/关闭/设置数值”动作，不负责自动待机或学习用户习惯。

## 3. 用户与典型场景

### 3.1 用户角色

| 角色 | 需求 |
| --- | --- |
| 宿舍学生 | 通过场景演练快速理解自动化效果 |
| 规则设计者 | 新建和调整规则，观察冲突并修改优先级 |
| 课程验收者 | 查看规则执行日志、测试报告和持久化恢复结果 |

### 3.2 核心用户旅程

1. 打开应用，恢复上次环境、设备、规则与日志。
2. 在实验室页拖动温度、湿度、光照或 CO₂ 滑块，模拟传感器输入。
3. 点击“执行联动规则”，观察命中规则、设备状态和冲突提示。
4. 切换到规则页，新增规则或编辑现有规则；可通过场景演练复现两个条件同时满足的情况。
5. 切换到日志页，查看环境快照、命中条件、设备变化顺序和冲突仲裁。
6. 结束应用进程后重新打开，确认数据恢复。

## 6. 数据模型

### 6.1 环境与设备

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| `EnvironmentState` | `temperature: number`、`humidity: number`、`illuminance: number`、`co2: number` | Mock 环境当前值 |
| `DeviceState` | `id`、`name`、`kind`、`power`、`value`、`minValue`、`maxValue`、`hasPower`、`hasValue`、`valueLabel`、`unit`、`accent`、`shortName` | 设备当前状态及展示元数据 |
| `DeviceKind` | LIGHT / AC / CURTAIN / HUMIDIFIER / PURIFIER | 5 类设备 |

### 6.2 规则与执行

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| `RuleCondition` | `metric: EnvMetric`、`operator: CompareOperator`、`value: number` | 单个触发条件 |
| `RuleAction` | `deviceId: string`、`power?: boolean`、`value?: number` | 单个设备动作 |
| `AutomationRule` | `id`、`name`、`enabled`、`priority`、`conditions`、`actions`、`revision` | 规则实体；revision 用于列表刷新 |
| `DeviceChange` | `deviceId`、`deviceName`、`field`、`fromText`、`toText`、`ruleId`、`ruleName` | 单次设备变化 |
| `ConflictRecord` | `ruleId`、`ruleName`、`deviceId`、`deviceName`、`field`、`requested`、`keptByRuleName` | 冲突仲裁记录 |
| `ExecutionRecord` | `id`、`timestamp`、`scenario`、`environment`、`executedRuleIds/Names/Conditions`、`changes`、`conflicts`、`summary` | 一次执行日志 |
| `PersistedState` | `version`、`environment`、`devices`、`rules`、`logs` | 本地存档根对象 |

### 6.3 存储约定

- Preferences 名称：`linkage_lab_store`。
- 状态 key：`lab_state_v1`。
- 当前版本号：`1`。
- 日志上限：30 条；规则上限：50 条（解码清洗时截断）。
- 数值边界：温度 0—40、湿度 0—100、光照 0—2000、CO₂ 400—2000；设备数值按设备 `minValue/maxValue` clamp。
- 编码格式：JSON 字符串；读取时使用 `StateCodec.decode` 完成版本校验、规则/日志过滤和数值修正。

## 7. 业务规则

### 7.1 条件判定

- 环境指标取值：温度、湿度、光照、CO₂。
- 比较符：`>`、`>=`、`<`、`<=`。
- 每条规则 1—2 个条件，全部满足才命中（AND）。
- 停用规则不参与判定。

### 7.2 执行顺序与冲突

1. 过滤启用规则。
2. 按 `priority` 降序排序；优先级相同按 `id` 升序。
3. 逐条匹配规则，命中后按动作顺序应用。
4. 对每个设备字段（`deviceId:power` 或 `deviceId:value`）设置字段锁：
   - 首个写入的规则成为保持者；
   - 后续规则若请求不同值，则动作被跳过，并记录 `ConflictRecord`；
   - 若请求相同值，不产生冲突，也不重复写入。
5. 记录设备变化（仅记录实际变化的字段）和命中条件。
6. 生成 `ExecutionRecord` 并保存。

### 7.3 默认规则

| 规则 | 条件 | 动作 | 优先级 |
| --- | --- | --- | --- |
| 高温遮阳 | 温度 ≥ 30°C 且 光照 ≥ 1200lx | 窗帘开合度 20% | 50 |
| 深夜护眼 | 光照 < 60lx | 主灯开启，亮度 25% | 45 |
| 闷热除湿 | 温度 ≥ 26°C 且 湿度 ≥ 70% | 空调开启，目标 25°C | 35 |
| 高温制冷 | 温度 ≥ 28°C | 空调开启，目标 24°C | 30 |
| 干燥加湿 | 湿度 < 35% | 加湿器开启 | 25 |
| 暗光照明 | 光照 < 150lx | 主灯开启，亮度 60% | 20 |
| 空气净化 | CO₂ ≥ 1200ppm | 净化器开启，风速 2 档 | 15 |

### 7.4 默认场景

| 场景 | 温度 | 湿度 | 光照 | CO₂ | 预期联动 |
| --- | --- | --- | --- | --- | --- |
| 夏夜闷热 | 29°C | 78% | 40lx | 900ppm | 照明 + 除湿 + 制冷，产生 2 处冲突 |
| 清晨强光 | 31°C | 46% | 1600lx | 620ppm | 遮阳 + 制冷 |
| 冬日干燥 | 17°C | 26% | 320lx | 560ppm | 加湿 |
| 自习归来 | 27°C | 62% | 120lx | 1450ppm | 照明 + 净化 |

## 8. 边界与异常需求

| 情况 | 处理 |
| --- | --- |
| 规则列表为空或全部停用 | 不修改设备，日志记录“未命中”；不抛异常 |
| 规则动作引用未知设备 | 跳过该动作，继续执行其余动作 |
| 设备数值超出范围（如亮度 150%） | 按设备上下限 clamp（100%） |
| 优先级相同 | 按规则 ID 升序，保证执行顺序确定 |
| 同字段多规则请求 | 先执行者锁定，后执行者让位并记录冲突 |
| 存档为空、损坏或版本不符 | `decode` 返回 null，应用回退默认数据 |
| 存档规则条件为空/动作为空 | 清洗时丢弃该规则 |
| 日志超过 30 条 | 保存/恢复时截断为最近 30 条 |
| Preferences 保存失败 | 保留内存状态，界面显示“本地保存失败” |
| 应用进程结束 | 每次变更即时或防抖保存，重启恢复 |

## 9. 页面与交互设计

### 9.1 实验室页

- 顶部：应用名称、本地存档状态、保存时间。
- 统计条：规则总数、启用规则、在线设备、执行记录。
- 场景演练：横向 4 张场景卡片，一键注入环境并执行。
- Mock 环境：4 个滑块，拖动结束立即保存。
- 最近联动横幅：命中规则数、设备变化数、冲突数、执行顺序。
- 设备矩阵：2 列设备卡片，手动控制开关与参数。
- 执行按钮：按当前环境执行联动。

### 9.2 规则页

- 规则重叠提示和统计。
- 按优先级降序显示规则；展示 IF/THEN、优先级、启停、编辑和删除。
- 新建/编辑弹层：基础信息、最多 2 个条件、最多 3 个动作、实时优先级。
- 删除与清空操作使用确认弹窗。

### 9.3 日志页

- 按时间倒序展示执行记录。
- 每条记录展示场景、时间、环境快照、执行顺序、命中条件、设备变化、冲突和摘要。
- 清空日志需要确认；规则和设备状态不受影响。
